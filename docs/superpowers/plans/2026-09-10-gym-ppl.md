# gym-ppl Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Página estática en español para consultar ejercicios push/pull/pierna/core con GIF, técnica, músculos trabajados y consejos, usando el dataset hasaneyldrm/exercises-dataset.

**Architecture:** HTML/CSS/JS vanilla, sin build. Un script Python (stdlib) descarga el dataset upstream, genera `data/library.json` (1,324 slim) y `data/ppl.json` (curado). Media por CDN jsDelivr. Publicación en GitHub Pages.

**Tech Stack:** Python 3 stdlib, HTML/CSS/JS vanilla, GitHub Pages, jsDelivr CDN.

## Global Constraints

- Sin frameworks, sin bundler, sin backend, sin base de datos.
- Solo stdlib de Python (`urllib`, `json`, `csv`).
- CDN base: `https://cdn.jsdelivr.net/gh/hasaneyldrm/exercises-dataset@main/`
- Atribución obligatoria: `© Gym visual — https://gymvisual.com/` visible en cada ficha y en el pie.
- No commit ni push sin OK explícito del usuario.
- Verificar guías de entrenamiento contra literatura antes de escribirlas (cita inline), y marcar lo no verificado como ⚠️ NO-VERIFICADO. Disclaimer: no es consejo médico.

### Task 1: Pipeline de datos + library.json

**Files:**
- Create: `.gitignore`
- Create: `scripts/build_data.py`
- Test: ejecución del script + revisión de salida

**Interfaces:**
- Produces: `data/raw/exercises.json` (upstream crudo), `data/library.json` (array de 1,324 objetos slim).
- Slim record: `{id, name, body_part, equipment, target, secondary_muscles[], steps_es[], image, gif_url}`; `image`/`gif_url` convertidos a URL CDN.
- Produce además `data/raw/facetas.txt` con los valores distintos de `target`, `body_part`, `equipment` (insumo para la curación).

- [ ] **Step 1:** Crear `.gitignore` con `data/raw/` y `.DS_Store`.
- [ ] **Step 2:** Escribir `scripts/build_data.py`:
  - `download(url, dest)` con urllib; descarga solo si no existe.
  - `slim(rec, cdn)` → dict con los campos de arriba; `steps_es` desde `instruction_steps["es"]` (fallback: partir `instructions["es"]` por ". ").
  - `main()`: descarga upstream a `data/raw/exercises.json`, valida que sean 1324, escribe `data/library.json` (JSON compacto, `ensure_ascii=False`) y `data/raw/facetas.txt`.
- [ ] **Step 3:** Ejecutar `python3 scripts/build_data.py` y verificar: `library.json` con 1,324 records, primer record `id="0001"`, `image` inicia con la URL CDN. La salida imprime conteos por `body_part`.
- [ ] **Step 4:** Revisar `data/raw/facetas.txt` y fijar en el script el mapa día↔target (dict `DAY_BY_TARGET` + fallback `DAY_BY_BODY_PART`) con los valores reales del dataset.
- [ ] **Step 5:** Re-ejecutar y confirmar que el script no falla. (Sin commit hasta OK del usuario.)

**Acceptance:** `data/library.json` existe, 1,324 registros, campos completos, URLs CDN, mapa de días sin targets huérfanos.

### Task 2: Curación + ppl.json + check.py

**Files:**

**Interfaces:**
- `curacion.csv` columnas: `id,dia,orden,nombre_es,tip,clave,sesion`; `dia ∈ {push,pull,pierna,core}`; `sesion ∈ {sugerido,opcion}`.
- `data/ppl.json`: array de records slim + `{dia, orden, nombre_es, tip, clave, sesion, attribution}`.
- `check.py` (exit 1 si falla, imprime `OK` al final): JSONs válidos; 1324 library; ids curados existen y tienen campos no vacíos; `dia` consistente con el mapa; 25±2 por día PPL; `sesion=sugerido` entre 6 y 8 por día PPL; con `--online` verifica HEAD 200 de `gif_url`/`image` de los curados.

- [ ] **Step 1:** Seleccionar los 75 PPL (25 push / 25 pull / 25 pierna) + ~8 core desde `library.json`, balanceando músculo y equipo (compuestos primero). Escribir `curacion.csv` con nombre_es, tip ("cómo sentirlo") y clave ("error típico") por fila.
- [ ] **Step 2:** Extender `build_data.py` para leer `curacion.csv`, cruzar por id (error claro si falta), escribir `ppl.json` e imprimir cobertura por `dia`/`target`.
- [ ] **Step 3:** Escribir `check.py` con los asserts de arriba (sin frameworks).
- [ ] **Step 4:** Ejecutar `python3 scripts/build_data.py && python3 scripts/check.py` → `OK`. Corregir ids/tips hasta pasar.
- [ ] **Step 5:** Ejecutar `python3 scripts/check.py --online` (solo los ~83 curados) → `OK`.

**Acceptance:** check.py pasa en ambos modos; cobertura PPL razonable por músculo; tips y claves en español sin campos vacíos.

### Task 4: UI (index.html + app.js + styles.css)

**Files:**
- Create: `index.html`, `app.js`, `styles.css`

**Interfaces:**
- `ppl.json` y `guias.json` embebidos vía fetch al cargar; `library.json` fetch diferido al primer uso del buscador.
- Navegación por hash: `#push`, `#pull`, `#pierna`, `#core`, `#buscar`, `#detalle/<id>`; botón atrás del celular funciona.
- `renderDia(dia)`: nota + cobertura (conteo por `target`) + "Sesión sugerida" (`sesion=sugerido`) + "Más opciones" + guía del día.
- `renderDetalle(id)`: GIF grande, pasos numerados `steps_es`, tip, clave, equipo, músculos (target + secondary), atribución.
- Buscador: input + filtros día/músculo/equipo sobre `library.json`; fallback a datos ya cargados si el fetch falla.
- Mobile-first, dark, sin dependencias; `loading="lazy"` en GIFs.

- [ ] **Step 1:** Escribir `index.html` (estructura + footer con licencias/atribución/disclaimer).
- [ ] **Step 2:** Escribir `styles.css` (mobile-first, dark, tarjetas, chips, modal detalle).
- [ ] **Step 3:** Escribir `app.js` (router hash, fetch de datos, renders, buscador).
- [ ] **Step 4:** Probar local: `python3 -m http.server 8080` y abrir `http://localhost:8080`; smoke manual: home → Push → detalle → atrás → buscador → filtro (ver lista de smoke abajo).
- [ ] **Step 5:** (Si playwright-cli disponible) smoke automatizado mínimo: cargar página, clic en Push, assert ≥10 tarjetas, abrir detalle, assert pasos > 0. Si no está disponible, dejar constancia del smoke manual.

**Smoke manual:** (1) home muestra 3 días + core; (2) Push lista sesión sugerida y cobertura; (3) detalle muestra GIF y pasos numerados; (4) atrás vuelve al día; (5) buscador filtra por "biceps" y por equipo "dumbbell"; (6) footer muestra atribución Gym Visual y disclaimer; (7) sin errores en consola.

**Acceptance:** smoke completo sin errores de consola; GIFs cargan desde CDN; atribución visible.
